# 00 · 执行摘要

## 一句话方案

构建一个以后端可信性为中心的匿名健康测评系统：每个步骤原子持久化，用户可恢复进度；提交后由版本化纯函数生成 BMI、建议摄入量和目标日期；结果接口每次实时检查订阅；模拟支付以幂等事务完成权限升级；全部关键路径由真实数据库集成测试与浏览器 E2E 证明。

## 评分维度对应策略

| 评分维度 | 本项目的核心回答 |
|---|---|
| API 设计 | `/api/v1`、资源化路径、完整一步用 PUT、ETag/If-Match、RFC 9457 风格错误、OpenAPI |
| DB 设计 | 强类型核心输入、不可变版本化结果、订阅与支付事件分离、双层约束、RLS、迁移唯一事实源 |
| 流程闭环 | 安全匿名 session、恢复、状态机、提交计算、preview/full 投影、`/pay` 幂等闭环 |
| 测试与质量 | 边界表、属性测试、真实 DB 并发测试、字段泄露负向断言、Playwright、CI |
| AI 效率 | 让 AI 生成候选模型/测试，再用约束、差分验证、agent review 与运行证据筛选，而非直接接受 |

## 范围

### 必须完成

- 匿名会话创建、续用和过期处理。
- 性别/计算参数、目标、年龄、身高、当前体重、目标体重、运动频率的分步保存。
- 刷新、关闭后恢复答案、完成步骤、下一步与 revision。
- 服务端 BMI、BMR/TDEE、建议热量、目标日期和预测曲线计算。
- 结果及输入快照持久化，算法版本可追踪。
- 非会员 preview 与会员 full 的服务端差异化返回。
- `POST /api/v1/pay` 模拟支付、状态变化、重放安全。
- 自动化单元、集成、API E2E 和浏览器 E2E。
- GitHub Actions、Vercel 线上演示、README、OpenAPI、ERD、AI 复盘。

### 明确不做

- 真实 Stripe/Apple Pay、退款、税务和账单。
- 医疗诊断、个体化治疗建议、未成年人流程。
- 完整注册登录、找回密码、社交登录。
- 管理后台、营销分析平台、复杂 A/B 实验系统。
- BetterMe 的像素级复制、素材复制或其全部长问卷。

## 关键质量属性

1. **安全**：session token 不落明文；客户端不能指定 `userId` 或 `subscriptionStatus`；他人资源返回 404；日志不记完整 token/健康载荷。
2. **一致性**：进度、答案、revision、幂等记录在事务中更新；提交与结果写入原子完成；支付事件与订阅更新原子完成。
3. **可解释**：计算结果保存 `algorithm_version`、`input_snapshot`、时间与中间量。
4. **可恢复**：恢复接口返回服务端事实；健康答案不落 localStorage，未保存字符只在页面内存中。
5. **可验证**：每条关键业务规则都有自动化测试或线上 smoke 证据。
6. **可演进**：问卷版本、算法版本、订阅计划、扩展问题均可新增而不破坏既有结果。

## 两天交付原则

- 单体优先：一个 Next.js 应用、一个 Supabase 项目、一次 Vercel 部署。
- 先打通后端纵切：session → save → restore → submit → result → pay；UI 在 API 稳定后接入。
- 测试契约先在文档中冻结；按用户指定顺序先完成全部功能与 typecheck/build，再由独立 agent 集中实现测试矩阵，主 agent 复核并修复。这样保留测试独立性，但必须为集中测试阶段预留硬时间。
- 不以“手工点过一次”作为完成；必须有可重放命令或自动化证据。

## Done 的定义

只有同时满足以下条件才算交付：

- 公网 URL 可从零完成漏斗与模拟支付。
- README 的 cURL 从新 session 走到 preview → pay → full 可重放。
- 有一个只含合成数据、DB/RPC 强制只读、已支付且可轮换的 demo session。
- `pnpm test` 一键通过核心单元与集成测试，`pnpm verify` 通过全部门禁。
- GitHub Actions 主分支绿色，迁移可从空库重建。
- 非会员响应的保护字段递归断言为不存在。
- Supabase security/performance advisors 无未解释的高风险项。
- 文档覆盖启动、API、Schema、测试、部署、已知限制和 AI 复盘。
